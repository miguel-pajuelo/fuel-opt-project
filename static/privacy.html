Privacidad

Cómo trata FuelOpt los datos durante su uso en el equipo.

Funcionamiento local

FuelOpt se ejecuta en tu equipo y sirve la interfaz desde una dirección local. No existe un servidor central de FuelOpt, telemetría propia, analítica, GoatCounter ni otros trackers. Tus búsquedas no se envían automáticamente a FuelOpt ni se asocian a una cuenta o perfil.

SQLite almacena localmente el catálogo, los precios y sus metadatos. La configuración no secreta vive en %LOCALAPPDATA%\FuelOpt\config.json; la base activa, caché y logs se guardan bajo %LOCALAPPDATA%\FuelOpt. El navegador utiliza localStorage únicamente para recordar que cerraste la ayuda inicial, mediante la clave fuelopt:onboarding:v1:dismissed.

OpenRouteService y rutas aproximadas

La clave de OpenRouteService (ORS) se guarda preferentemente como credencial del usuario en Windows Credential Manager. En desarrollo puede utilizarse una variable de entorno local. FuelOpt no la guarda en config.json.

Cuando se usa ORS, el servicio puede recibir las direcciones, coordenadas y puntos necesarios para geocodificar o calcular una ruta. Si ORS no está disponible, FuelOpt puede utilizar Haversine: una estimación geográfica calculada localmente que no conoce carreteras, sentidos, barreras ni tráfico.

Otros servicios externos

  • OpenStreetMap: Leaflet se incluye localmente, pero el navegador solicita a tile.openstreetmap.org las teselas del área visualizada. El proveedor puede recibir la IP y datos técnicos de esas solicitudes. El mapa muestra la atribución © OpenStreetMap contributors.
  • Google Maps: no recibe una consulta automáticamente. Solo recibe el origen, el destino y la estación cuando pulsas voluntariamente Abrir en Maps.
  • GitHub: solo recibe información cuando abres Mándanos tu idea y decides crear o publicar un Issue. FuelOpt no completa el Issue con datos de tu búsqueda.
  • MINETUR: es la única fuente productiva del catálogo. FuelOpt consulta el catálogo oficial del Ministerio de Industria y Turismo para actualizar estaciones y precios. Esas peticiones no envían tus búsquedas personales, aunque el proveedor puede ver la IP y datos técnicos de la actualización.

FuelOpt ya no utiliza SMTP ni solicita una dirección de correo dentro de la aplicación. Cada servicio externo aplica sus propias condiciones y políticas.

Logs y diagnóstico

Los logs normales pueden registrar fechas, operaciones y tipos generales de fallo. Las fronteras ORS evitan registrar claves, URLs sensibles, parámetros de consulta, cabeceras Authorization o texto crudo de excepciones de red. El modo diagnóstico puede generar más información técnica y debe utilizarse con prudencia antes de compartir archivos.

Estas medidas reducen el riesgo de exposición, pero no implican seguridad total ni anonimato garantizado. Los servicios externos pueden ver la IP desde la que reciben una solicitud.

Conservación y eliminación

Los datos locales permanecen hasta que los borras. La desinstalación conserva por defecto %LOCALAPPDATA%\FuelOpt; solo lo elimina si eliges la opción explícita o utilizas /REMOVEDATA=1. La credencial ORS puede borrarse con FuelOpt.exe --clear-ors-key.

Ideas, errores y seguridad

Mándanos tu idea abre GitHub Issues para ideas y errores no sensibles. No publiques allí claves, credenciales, datos personales ni detalles explotables. Para vulnerabilidades, sigue la política y las opciones privadas de seguridad del repositorio cuando estén disponibles.
